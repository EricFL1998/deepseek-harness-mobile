01为什么不再截图驱动#

截图只能证明“这里少了一块”，证明不了“还有多少块没接”。源码清单可以。

旧方式

用户截图 → 改一处

每次只修被看见的 UI，slot、entry、RPC、空态、权限态仍可能漏；回归也没有清单可对。

新方式

源码 → 清单 → 实现

扫描插件注册的 slot/entry/component 与数据依赖，生成可执行报告；缺口由 --check 拦截。

结果

4/4 落点可验证

订阅插件从“2 个完全没写、1 个部分实现”到扫描器全部通过，且能持续复跑。

核心原则

先清单、后界面；先覆盖、后像素。截图只用于视觉验收，不作为发现 UI 的来源。

02整体架构#

插件源码在左，原生 UI 在右；扫描器负责把“插件有什么”变成“原生要接什么”。

1
插件源码source map / TSX / client.js
2
Plugin Scannerslot · entry · component · RPC
3
UI ManifestJSON + Markdown 缺口清单
4
Native CompanionPageContent · SlotContribution
5
Verify--check · SlotCoverageTest
Host 侧

插件逻辑不动

OAuth、token、模型调用、数据查询仍留在 JS 插件；原生只通过 RPC 取展示数据。

App 侧

slot 宿主与能力桥

每个位置由 NativeSlotHost / OfficialSlot 承载； PluginRpcHost、PluginModelHost 提供受控能力。

03输入与准备#

第三方开发者不需要 DSH upstream，只需要自己已经发布的插件包或源码仓库。

输入优先级说明
lib/*.js.map首选发布包里通常带 sourcesContent，可还原原始 TSX，信息最全。
src/**/*.tsx次选开发仓库的直接源码；没有 map 时使用。
lib/client.js兜底编译产物；仍能识别 slot/entry/component，JSX 树是启发式。
原生伴侣源码可选--companion 用来判断插件 slot 是否真的被伴侣实现。
 
# 仓库根目录（App 开发环境）
python tools/plugin_ui_scanner.py --help

# SDK 交付包里也带同一份扫描器
python tools/plugin_ui_scanner.py \
  --plugin /path/to/your-plugin \
  --companion /path/to/native-companion/src \
  --write docs/plugin-ui.md \
  --json docs/plugin-ui.json \
  --check
不需要官方源码

扫描器只读插件包。官方 slot 清单由 App 的 NativeSlotMapping 提供； 第三方环境无需 dsh-upstream。

04扫描插件源码#

一次扫描，得到插件全部 UI 挂载点与它们需要的数据。

你的插件包/ ├─ package.json name / version / 依赖 ├─ lib/ │ ├─ client.js 编译产物（兜底） │ └─ client.js.map sourcesContent 含原始 TSX（首选） ├─ src/ 开发仓库源码（次选） │ ├─ client/index.ts │ ├─ client/UsageChip.tsx │ └─ client/SettingsSection.tsx └─ locale/*.json 文案表

扫描器识别什么

挂载点

ctx.slots.register({ name, id, order, mode }, Component)； 同时识别 slots.inject / children 关系。

数据依赖

useProjection('...')、useChat/useSession、 inject face、插件 RPC 方法名。

UI 结构

组件 JSX 树、可见文案、按钮动作、locale key； 用于确认空态、表单、错误提示等是否都接。

定位 / 交互

useAnchoredPosition、createPortal、 anchorRef、role="dialog"、side/align 等锚定线索； 伴侣若用居中 Dialog 会提示与 anchored popover 不一致。

缺口

未映射 slot、无宿主 NativeSlot、传入 --companion 但伴侣未注册对应贡献，三类都会报。

命令示例：订阅插件

python tools/plugin_ui_scanner.py \
  --plugin .captures/sub-pkg/dsh-plugin-subscription-oauth \
  --companion samples/subscription-native/src/main/kotlin \
  --json .captures/plugin-ui.json \
  --check

扫描结果为 4 个落点、20 个 RPC；其中 settings.models.provider-card 最初被标为“未映射 / 未实现”。

05读懂扫描报告#

报告不是给人“参考”的，而是逐行对应实现任务。

列含义怎么用
slot官方 slot 名在 NativeSlotMapping 找目标落点
entry同一 slot 下的子条目如 composer.dock 的 activity/usage，可拆独立落点
component注册的 React 组件用来读源码与确定 UI 结构
原生落点映射到的 NativeSlot为空 = App 还没认领这个位置
宿主App 是否有 NativeSlot 容器否 = 即使有映射也不会显示
原生实现伴侣是否注册贡献/页面否 = 插件有 UI、伴侣没写
数据依赖projection / RPC / inject决定原生用 PluginRpcHost 还是 spec 下发
定位/交互anchored popover / portal / dialog 等线索决定用锚定 Popup 还是 Dialog，避免“结构对、位置不对”

订阅插件的原始缺口

落点组件初次扫描状态处理
conversation.composer.dockUsageChip部分实现补面板明细、bonus、重置时间、60s 刷新
conversation.input.rightFastModeButton完全没写新增 PluginModelHost + FastModeContribution
settings.models.provider-cardProviderCardExtras完全没写新增 SETTINGS_PROVIDER_CARD 宿主 + 卡片
settings.sectionSubscriptionsSection大部分实现补 auto 链、设备码复制/有效期、目录标签

06选择实现方式#

先按形态选容器，再按数据选能力；不要所有东西都写成一个 Compose。

扫描结果原生实现典型例子
设置页 / 独立页面PageContent + PageRegistrySubscriptions 整页、账号管理
输入栏、消息、dock、卡片扩展SlotContribution额度胶囊、fast-mode、provider 卡片
官方控件本身OfficialSlot 包装默认 UItok/s、缓存命中、上下文、发送按钮
信息型卡片 / 列表 / 指标SpecSlotContribution + dsh-ui spec状态卡、用量面板、配置摘要
需要切模型/推理档位PluginModelHost.selectModelfast 模式按钮
暂时没有宿主显式 Web 回退未认领的新 slot
能力缺失要显式记录

如果伴侣需要“切模型”或“写文件”等 App 能力，先加可选 SDK 接口（参考 PluginRpcHost / PluginModelHost），不要偷偷绕过。

07宿主能力与数据契约#

原生端不建网络连接、不持有 token；能力由 App 注入，数据由 Host 插件提供。

PluginRpcHost

调用插件既有 RPC

rpc.callRpc(
  "subscription-oauth.status",
  JsonObject(emptyMap())
) { result -> ... }
PluginModelHost

切换模型 / reasoning

host.selectModel(
  provider = "kimi",
  model = "kimi-for-coding",
  reasoningEffort = "highspeed"
)
spec

App → slot 的状态

slot spec 只放展示/选择状态，例如 modelId、reasoningEffort、 provider、displayName。

更新

refresh / 轮询

长耗时逻辑留在 Host；原生按 60s 轮询或等 client/refresh， 不要自己维护业务状态。

禁止

原生 APK 内出现 token / API key / 任意文件路径；所有敏感数据留在 Host。

Popup 定位与材质（扫描器新增）

Web 版 useAnchoredPosition / createPortal 的浮层不是居中 Dialog。原生统一用 SDK 的 PluginPopover：贴着触发元素上方、右对齐， 材质取 App 的 DshMenuCard 映射（表面色、发丝边、16dp 圆角、菜单阴影）， 不使用 Material Card 或硬编码颜色。

Web 线索原生实现
useAnchoredPosition / anchorRefPluginPopover，与触发元素同 Box
createPortal / role="dialog"Popup + PopupPositionProvider
side: 'top' / align: 'end'上方 6dp、右对齐、窗口内夹取
App 菜单材质colorPopupSurface / colorPopupBorder / cornerPopup
为什么第一次没扫出来

旧版扫描器只提取结构/文案/RPC，没有几何与定位。现在会提取 useAnchoredPosition、createPortal、side/align 等 placement 线索；伴侣若用 Dialog 而插件是 anchored popover，会直接告警。

10校验与 CI#

三道闸：插件覆盖、官方 slot 覆盖、App 单测。

Gate 1

plugin scanner --check

插件每个 slot 必须映射、有宿主、伴侣实现；否则 exit 1。

Gate 2

slot_inventory.py

官方 slot 映射与宿主一致；新增官方 slot 未处理会失败。

Gate 3

SlotCoverageTest

Kotlin 反射断言官方常量全集；CI 与本地一致。

# 本地 / CI 全量
python tools/plugin_ui_scanner.py --plugin <plugin> --companion <src> --check
python tools/slot_inventory.py --write docs/slot-inventory.md
./gradlew :app:testDebugUnitTest --tests com.deepseek.dsh.SlotCoverageTest
覆盖优先

UI 可以迭代，slot 覆盖不允许回退。新增官方 slot 时，测试/清单必须先失败再补齐。

11常见问题#

扫描器给出缺口后，按这些检查点排查。

扫描不到任何 slot？

确认插件包里有 lib/client.js.map 或 src/*.tsx； 仍不行时用 lib/client.js 兜底。检查 --plugin 路径是否指向包根目录。

报告说“未映射”怎么办？

这是 App 还没认领官方 slot。补 DshSlotRegistry 常量、NativeSlot、 NativeSlotMapping 和宿主；然后跑 slot_inventory.py。

映射了，但“宿主=否”？

UI 代码里没有真实出现 NativeSlot.X 容器。在对应页面/控件位置补 NativeSlot / OfficialSlot 调用。

扫描器说“伴侣未实现”怎么办？

插件有 slot 注册，但伴侣源码没有注册对应 SlotContribution / PageContent；或注册了错误的 NativeSlot。补贡献并重新扫描。

原生 UI 有数据但交互没反应？

slot 贡献拿到的是基础 PluginHostApi；需要 RPC 时确认 PluginRpcHost 已由 SlotBridgeHost 注入，App 已设置 NativeHost.rpcHandler。

截图看起来对了，还需要扫描器吗？

需要。截图只覆盖当前页面/状态；扫描器覆盖注册面、数据依赖和缺口， 防止“看起来对了但某个 slot 没接”。

13术语与版本#

快速查表。

术语解释
slot官方 UI 的挂载点；插件通过 ctx.slots.register 认领。
entry同一 slot 下的子条目，例如 dock 的 activity/usage；可拆成独立原生落点。
NativeSlot手机端原生容器位置；由 NativeSlotMapping 显式映射。
OfficialSlot官方控件的 slot 包装；默认内容 + 插件 ENHANCE/OVERRIDE。
PageContent整页原生 UI，注册到 PageRegistry。
SlotContribution嵌入型原生 UI，注册到 SlotRegistry。
SpecSlotContribution把 slot spec 里的 dsh-ui 结构交给 SpecRenderer 通用渲染。
PluginRpcHost调用插件既有 RPC 的宿主能力。
PluginModelHost切换模型/推理档位的宿主能力（fast mode）。
