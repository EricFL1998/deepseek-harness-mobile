Plugins & Native UI

Two plugin layers, one codebase

Host plugins follow the same rules as desktop; when native matters, add a native layer with the SDK.

Host plugins: same as desktop

Plugins keep running in the real DSH Host and register UI through official slots. Core slots map to Compose; web UI runs in the Web island.

  • Install / enable / uninstall like desktop
  • client-slots registrations are reused
  • Web island and native components mixed

Companion native UI：Kotlin + Compose

Ship native screens as APKs and register them into the right drawer, settings, composer and more with the DSH Native UI SDK.

// Register a guide capsule in the right drawer
class MyGuide : SlotContribution() {
  override val slot = NativeSlot.RIGHT_PANEL_GUIDE_ENTRY
  override val guideTitle = "My panel"
  override val guideDescription = "Native Compose page"
  @Composable override fun Render(...) { ... }
}

Architecture

On the phone, for real

A bundled Debian userland and Node runtime boot the upstream DSH; requests stay on the device.

On-device Host

  • Debian (glibc) + proot userland
  • Node 24 + upstream @deepseek-ai/dsh
  • Loopback Web GUI and bridge device capabilities
  • Pre-bundled Host entry, ~15.6s cold start

Android client

  • Native Kotlin + Jetpack Compose UI
  • Real workspace bound to shared phone storage
  • Remote + bridge channels keep plugin UI working
  • Open repository you can build yourself
