# v3.3 修订：让本地 Linux 运行时「不割裂」的无缝化设计

> **v3.4 补充**：系统原生文件系统接入（All files / SAF / 工作区三通道、路径映射、文件 UI）见 [`DSH-手机端-详细设计-v3.4-系统文件系统接入.md`](DSH-手机端-详细设计-v3.4-系统文件系统接入.md)。与本文 §6 的「一个文件入口」配合使用。

| 项 | 内容 |
|---|---|
| 版本 | v3.3（v3.0 本地运行时的体验层补充） |
| 日期 | 2026-10-17 |
| 问题 | Host 跑在本地 Linux 里，怎么让它和原生 App 融为一体，而不是「App 里藏着另一个系统」？ |
| 结论 | 关键不是隐藏 Linux，而是**把 Linux 降级为「不可见的引擎」**：统一状态机、统一生命周期、统一通知、统一文件入口、统一错误模型；用户只感知「App 和一个本地引擎」，不感知 proot、路径、端口、进程。 |

---

## 0. 割裂感从哪来

| # | 来源 | 用户感知 |
|---|---|---|
| 1 | 启动慢 | 打开 App 先看进度条/白屏，等 Linux 和 Node 起来 |
| 2 | 后台被杀 | 切出去任务就断、回来要重启、会话状态丢 |
| 3 | 状态不同步 | 原生 UI 显示已停止，Web 岛还能打开；或反过来 |
| 4 | 通知双份 | 系统通知 + 网页通知 + 前台服务通知各说各话 |
| 5 | 文件两套 | 「App 的文件」和「Linux 里的文件」不是一回事 |
| 6 | 错误黑盒 | 只看到「启动失败」，不知道是 rootfs、Node、端口还是 dsh |
| 7 | 更新打断 | 更新时任务被中断，或更新后数据/插件丢失 |
| 8 | 隐形常驻 | 用户不知道为什么后台一直有进程/耗电 |

**设计目标：让上面 8 条在 UI 上都变成「App 自己的状态」，而不是「另一个系统的事」。**

---

## 1. 五条统一原则

| 原则 | 含义 |
|---|---|
| **一个状态机** | App 与 Host 共用一个生命周期状态，UI 只渲染它；不存在两套「运行中」定义 |
| **一个通知管道** | 前台服务、审批、任务完成共用一个通知归属与去重逻辑 |
| **一个文件入口** | 用户只看到「工作区/文件」，不看到 Linux 路径；导入导出走 SAF |
| **一个错误模型** | proot/Node/dsh 的失败统一映射为产品错误码 + 修复动作 |
| **一个开关** | 用户能看见、能停止、能设置「空闲停止/常驻」，不做隐形守护进程 |

---

## 2. 状态机与生命周期编排

### 2.1 对外状态

```kotlin
sealed interface LocalEngineState {
    data object NotInstalled : LocalEngineState
    data class Installing(val stage: InstallStage, val progress: Float) : LocalEngineState
    data class Starting(val stage: StartStage) : LocalEngineState
    data object Ready : LocalEngineState                 // 可连接、可发消息
    data class Busy(val tasks: Int) : LocalEngineState   // 有 agent 回合在跑
    data object Stopping : LocalEngineState
    data object Stopped : LocalEngineState
    data class Failed(val code: EngineError, val recoverable: Boolean) : LocalEngineState
}
```

- `Ready` 之上再叠 `ConnectionState`（连接中/已连接/重连）；UI 不直接看 proot 进程。
- 所有页面（会话列表、聊天、设置、运行时页）都从同一个 `LocalEngineState` 派生，避免「一边说没起来、一边能打开」。

### 2.2 生命周期策略

| App 状态 | 有任务在跑 | 引擎策略 |
|---|---|---|
| 前台 | 否 | 保持运行（温启动） |
| 前台 | 是 | 保持运行 |
| 后台 | 是 | 前台服务 + WakeLock，常驻通知 |
| 后台 | 否 | 保持 N 分钟（默认 5，可配置）后停止 |
| 最近任务划掉 | 是 | 按设置：继续（FGS）或停止并提示 |
| 最近任务划掉 | 否 | 停止 |
| 重启手机 | — | 仅当用户开启「开机恢复」或存在待执行 schedule 时启动 |
| 更新安装 | — | 先停任务，空闲时切换；任务中不更新 |

### 2.3 启动与停止的原子性

- 启动：单例锁 → 检查安装 → 启动 proot → 起 dsh → 等就绪 → 连接。任何一步失败进入 `Failed`，**不在半启动状态暴露 UI**。
- 停止：`SIGTERM` → 等待 → `SIGKILL` → 校验进程组退出；重复调用幂等。
- 崩溃：指数退避重启；5 分钟内 3 次失败 → 安全模式（只提供诊断/重装/备份）。
- 任务中断：重启后以 Host 会话状态为准，标记「可能中断」，**不自动重发 prompt**（避免重复执行）。

## 3. 启动/恢复体验

### 3.1 分级呈现

| 耗时 | 呈现 |
|---|---|
| < 1.5 s | 不显示加载态，直接进会话列表 |
| 1.5–5 s | 顶部细进度条 + 「正在启动本地引擎」 |
| > 5 s | 分阶段进度（解压/启动/连接）+ 可取消 + 失败修复入口 |
| 首次安装 | 独立安装页：阶段、体积、可断点续装、可后台 |

### 3.2 冷启动路径

1. 原生 UI 先渲染（缓存会话列表、草稿、设置）。
2. 并行启动引擎；UI 显示「本地引擎启动中」的轻量状态。
3. 就绪后刷新会话列表与连接。
4. 首屏不等待引擎：用户可以先看缓存、改设置、读历史。

### 3.3 温启动

- App 在前台/近期使用过 → 引擎保持运行，重连而不是重启；目标「点开即可用」≤ 800 ms。
- 保留 token/cookie 与连接 generation；避免每次重新交换。
- 空闲停止后再次打开：显示「恢复本地引擎」（通常 2–5 s），不重装。

### 3.4 首次安装

- 六步流水线（解压 → 工具 → Node → pnpm → dsh → 补丁），每步可重试、可跳过已完成步骤。
- 展示总体积与磁盘占用；低存储提前阻止。
- 安装可后台（前台服务），失败不破坏已完成产物。

## 4. 后台保活（Android 限制下的现实方案）

| 机制 | 用途 | 注意 |
|---|---|---|
| **前台服务 `specialUse`** | 本地引擎/长任务 | Android 14+ 声明类型与权限；常驻通知；用户可见 |
| **WakeLock（PARTIAL）** | Agent 回合执行期间 | 仅任务中持有；结束立即释放 |
| **精确闹钟** | schedule 到点唤醒 | 需 `SCHEDULE_EXACT_ALARM`；被拒则降级并提示 |
| **电池优化白名单** | 降低被杀概率 | 首次启动引导；不强制 |
| **`onTaskRemoved`** | 划掉任务后的决定 | 按设置继续或停止 |
| **BOOT_COMPLETED** | 开机恢复 | 仅用户开启时；重登记 schedule |

**不做**：用 WorkManager 轮询「保活」；无通知的隐形守护进程；伪造前台服务类型。

### 4.1 用户可见的控制

设置 → 本地引擎：
- 运行状态、启动/停止、重启；
- 「空闲后停止」时长（5/15/30 分钟/常驻）；
- 「后台继续运行任务」开关；
- 「开机恢复」开关；
- 电池优化状态与一键跳转；
- 当前占用的 CPU/内存/磁盘。

## 5. 通知与深链

### 5.1 一个通知管道

| 通知 | 渠道 | 行为 |
|---|---|---|
| 前台服务 | `engine`（低） | 常驻，显示「本地引擎运行中 / 任务数」，点击进 App，含「停止」 |
| 任务完成 | `session_done`（低） | 汇总，同一会话去重 |
| 审批/提问 | `approval`（高） | 动作：允许/拒绝/打开 |
| 错误 | `engine_error`（中） | 修复入口 |

- **禁止**：网页通知与原生通知同时出现（Web 岛内关闭 Notification，由原生统一发）。
- 去重键：`(sessionId, turnId)`、`(approvalId)`；同一事件只发一次。
- 锁屏默认隐藏正文，可配置。

### 5.2 深链

- `dsh://session/{id}`、`dsh://approval/{id}`、`dsh://engine`；未就绪时先启动引擎再跳转。
- 通知动作冷启动：先恢复引擎 → 校验认证 → 执行动作；失败只打开 App 并提示。

## 6. 文件与分享（消除「两套文件」）

| 场景 | 做法 |
|---|---|
| 导入 | SAF 选择文件 → 复制到工作区 `inbox/` → Agent 可见 |
| 导出 | Agent 产物 → 原生「保存到…」SAF |
| 分享到 DSH | `ACTION_SEND` 接收 → 入 inbox → 打开会话 |
| 从 DSH 分享 | 原生分享面板（文件 URI 走 FileProvider） |
| 文件浏览 | 原生列表展示工作区；不显示 `/root/...` |
| 下载 | 原生下载管理器 + 通知 |
| 外部打开 | 原生 Intent + MIME 校验 |

原则：**用户永远看到「App 的文件」，Linux 路径只在内部使用。**

---

## 7. 更新与回滚（不打断）

| 步骤 | 设计 |
|---|---|
| 检查 | 后台检查 App/rootfs/DSH/插件版本；Wi-Fi + 充电时下载 |
| 下载 | 候选目录；校验和；断点续传 |
| 切换时机 | 无任务运行 + 用户确认（或「下次空闲自动」） |
| 原子切换 | 目录 rename/symlink 切换；保留上一代 |
| 失败 | 自动回滚到上一代；数据目录不动 |
| 数据 | 升级前快照（可导出）；迁移只前向 |
| 提示 | 不阻塞使用；「更新将在空闲时生效」 |

**禁止**：任务进行中更新；更新时清理用户数据；静默删除旧版本导致无法回滚。

---

## 8. 错误与修复（把黑盒变成可操作）

| 错误 | 用户看到 | 修复动作 |
|---|---|---|
| rootfs 缺失/损坏 | 「本地环境不完整」 | 重装环境（保留数据） |
| Node/dsh 缺失 | 「运行时组件缺失」 | 补装组件 |
| 端口占用 | 「端口冲突」 | 自动换端口 |
| 权限/SELinux/exec | 「系统限制」 | 引导设置/换安装方式 |
| 存储不足 | 「空间不足」 | 清理/扩容提示 |
| 启动超时 | 「启动超时」 | 重试 / 安全模式 / 导出日志 |
| 崩溃循环 | 「引擎反复退出」 | 安全模式 + 备份/重装 |

- 错误码与文案集中管理；不把 stderr 直接给用户（debug 可看）。
- 安全模式：只启动最小环境，提供备份、导出日志、重装、恢复。

---

## 9. 透明与控制

- 设置页展示：引擎版本、DSH 版本、rootfs 版本、运行时长、CPU/内存/磁盘、最近一次启动耗时。
- 「停止引擎」立即生效；「重启引擎」有确认。
- 日志导出（脱敏）一键生成。
- 首次使用明确告知：本机运行 Linux 环境、会占用存储/电量、Agent 可执行工具。

| 场景 | 目标 |
|---|---|
| 温启动到可交互 | ≤ 800 ms |
| 冷启动（已安装）到可交互 | ≤ 4 s |
| 首次安装 | 1–3 分钟（可后台） |

| 空闲 CPU | 接近 0（无轮询） |
| 引擎停止后残留进程 | 0 |
| 通知延迟 | 审批/完成 ≤ 1 s（本地） |

## 12. 反模式（评审时逐条检查）

- ❌ 每次启动重装/重置 rootfs。
- ❌ 启动页阻塞等待 proot，没有缓存首屏。
- ❌ 无通知的隐形后台进程。
- ❌ Web 岛通知 + 原生通知双份。
- ❌ 把 `/root/...` 路径暴露给用户。
- ❌ 用 WorkManager 轮询保活 Agent。
- ❌ 任务进行中更新/杀进程。
- ❌ 只显示「启动失败」，没有修复动作。
- ❌ 把核心聊天界面放 WebView 来「省事」。

## 13. 验收清单

- [ ] 一个状态机驱动所有页面
- [ ] 冷/温启动有分级呈现，首屏不阻塞
- [ ] 后台任务有前台服务 + 通知 + WakeLock，用户可停
- [ ] 通知单一管道、去重、动作可用
- [ ] 文件只走 App 入口，不暴露 Linux 路径
- [ ] 更新不打断任务、失败可回滚、数据不丢
- [ ] 错误有产品文案 + 修复动作 + 安全模式
- [ ] 运行时可观测、可停止、可导出日志
- [ ] 生命周期矩阵真机通过（含 OEM）

---

> **一句话**：不割裂的关键不是「把 Linux 藏起来」，而是**让 Linux 只以「引擎状态」的形式出现在产品里**：用户看到的是启动进度、任务状态、通知、文件、错误和开关，而不是 proot 进程、端口和 Linux 路径。
